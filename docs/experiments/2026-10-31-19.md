# 2026-10-31-19 KDE가 전역 단축키를 관리하는 구성 확인

2026-10-31 KST, 기본 키 조합 없이 동작을 등록하고 KDE 설정에서 키를 지정할 수 있는지 읽기 전용으로 확인했다. Waytoys 기준은 기존 develop `c02799b` 위 미커밋 상태이며 제품 코드·사용자 단축키는 바꾸지 않았다. Windows PowerShell의 `D:\Github\utils\way-toys`에서 조사했고 VM은 기존 Debian/KWin 6.3.6 Wayland다.

## 근거와 결과

- [KGlobalAccel API](https://api.kde.org/kglobalaccel.html)는 동작 등록과 기본/활성 키 조합을 분리하며, Autoloading으로 사용자가 KDE에서 저장한 할당을 다시 불러온다. 동작의 식별자는 재시작 후에도 같아야 한다.
- [공식 구현](https://github.com/KDE/kglobalaccel/blob/master/src/kglobalaccel.cpp)의 `setDefaultShortcut`/`setShortcut`은 빈 키 목록도 동작을 등록하는 경로로 처리한다. 여기서 읽은 master 코드는 현재 문서의 참고이며 VM 설치 버전과 동일한 커밋으로 간주하지 않는다.
- [KDE 단축키 설명](https://docs.kde.org/stable_kf6/en/plasma-desktop/kcontrol/keys/index.html)은 동작별 키 조합 지정과 미지정을 지원한다고 설명한다. 이 문서의 UI 설명은 오래된 Plasma 개정판을 포함하므로 정확한 현재 메뉴 배치를 검증한 것은 아니다.
- 따라서 Waytoys는 편집기 열기·레이아웃 적용·다음/이전 창 같은 전역 동작을 등록하고, 기본 키는 미지정으로 두며 KDE를 키 할당의 기준으로 사용할 수 있다. 앱 재실행 때 사용자 할당을 빈 값으로 덮어쓰는 방식은 피해야 한다.
- Shift 드래그 같은 수정키 상태와 에디터 안의 Esc/Ctrl+S는 전역 단축키 등록과 별도 입력 규칙이다.

## 실제 VM 확인 명령

```powershell
ssh debian@192.168.50.125 'XDG_RUNTIME_DIR=/run/user/1000 DBUS_SESSION_BUS_ADDRESS=unix:path=/run/user/1000/bus qdbus6 org.kde.kglobalaccel /kglobalaccel'
```

종료값 0으로 `doRegister`, `setShortcut`, `setShortcutKeys`, `defaultShortcutKeys`, 변경 신호 등을 제공하는 실제 인터페이스를 확인했다. introspection만 했고 등록·키 변경 메서드는 호출하지 않았다.

대안인 GlobalShortcuts 포털의 버전도 Properties.Get으로 조회를 시도했지만 해당 경로에서 메서드를 찾지 못했다. 이 결과만으로 포털 전체의 지원 여부를 단정하지 않는다. 이번 답변의 가능성 판단은 KDE 네이티브 KGlobalAccel 근거를 사용한다.

실제 미지정 동작 등록, KDE 설정 화면에의 노출, 사용자 할당과 재시작 후 유지, 충돌 처리의 실행 시험은 아직 하지 않았다. 제품 구현과 기본값 변경도 수행하지 않았으므로 빌드·테스트는 생략했다.
