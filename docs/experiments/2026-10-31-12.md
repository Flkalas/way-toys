# 2026-10-31-12 개발 캡처 도구 전체 흐름 검증

2026-10-31 KST, 환경과 미커밋 전체 화면 앱 변경은 [10](2026-10-31-10.md)과 같다. 정리 단계의 불필요한 clipboard keeper를 제거한 [capture-vm.ps1](../../scripts/capture-vm.ps1)을 검증했다.

Windows PowerShell, `D:\Github\utils\way-toys`에서 실행했다.

```powershell
& .\scripts\capture-vm.ps1 -Overlay
```

- VM 700의 기본 Plasma Wayland에서 전체 화면 오버레이 실행, Spectacle GUI 캡처, PVE Ctrl+C 입력, VM의 PNG 클립보드 읽기, SCP 전송, SHA-256 비교, Orca 탭 열기, 도구 소유 프로세스 종료까지 종료 코드 0이었다. 관찰 실행 시간은 약 9초다.
- 결과: `.artifacts/captures/20261031-034450-cb771d/clipboard.png`, 3922×1252. SHA-256 `3082358d2acb75004466e59e1c7ee49911b498e9ed0f82fa7f4cf8be621f9f2e`.
- 같은 디렉터리의 `manifest.json`, 출력 구성, 소스 상태와 앱 로그를 보존했다. 실제 도구 사본은 `executed-capture-vm.ps1`이다.
- 브라우저 탭에서 이미지 complete=true 및 원본 크기를 확인했다. PNG를 자르거나 재배율 처리하지 않았다.
- PowerShell 도구에 Windows Clipboard/Set-Clipboard/System.Drawing 호출이 없음을 정적으로 확인했다.
- 실패한 백그라운드 helper는 별도 실험 자료로 옮겼다. 개발 도구는 실제 성공한 GUI 복사 경로를 사용한다.
- 최종 상태에서 캡처용 systemd 유닛이 남아 있지 않고 기본 Plasma KWin이 active임을 확인했다.

기존 PNG만 가져오는 분기는 [13](2026-10-31-13.md)에서 별도로 확인했다. 사용법과 필요한 도구는 [VM 캡처 문서](../vm-capture.ko.md)에 있다.
