# 2026-11-03-06 X11 확장 시험에서 Esc 취소 실패 발견

## 목적·환경·코드

2026-11-03 KST, `/home/mark/Sources/way-toys`에서 수행했다. 기준 Git HEAD는 `47bd992`이고 X11 호환 구현의 미커밋 변경이 있었다. Debian 13.7, Linux 6.12.113+deb13-amd64, Rust/Cargo 1.99.1, KWin 6.3.6, Qt 6.8.2, Python 3.13.5, xclip 0.13, xdotool 3.20160805.1이다. Xvfb 패키지는 `2:21.1.16-1.3+deb13u4`다. Noto CJK/fontconfig를 사용했으며 글꼴 패키지의 정확한 버전은 미확인이다.

호스트는 KDE X11이지만 입력은 별도 Xvfb `1280x720x24`, KWin X11, D-Bus·XDG 디렉터리에서 실행했다. `XDG_SESSION_TYPE=x11`, `QT_QPA_PLATFORM=xcb`, `LIBGL_ALWAYS_SOFTWARE=1`, `KWIN_COMPOSE=O2`를 사용하고 `WAYLAND_DISPLAY`를 제거했다. 시험용 화면 잠금 서비스는 실제 잠금 화면이 아니다. systemd-run 래퍼는 클립보드 scope만 호스트 사용자 매니저로 연결하며 DISPLAY·XAUTHORITY는 시험 서버를 유지한다.

공통 의존성·준비·격리·정리는 [01회차](2026-11-03-01.md#공통-준비와-격리)를 따른다. 이 회차의 명령과 인수는 아래에 따로 적었다.

당시 시험 절차는 [2026-11-03-06/test-x11.py](artifacts/2026-11-03-06/test-x11.py), 소스 SHA-256은 [source-manifest.json](artifacts/2026-11-03-06/source-manifest.json)에 있다. 기준 HEAD 이후 파일이 변경되었으므로 HEAD만으로 당시 코드와 같다고 볼 수 없다.

## 실제 실행 순서

출력 판별·클립보드 읽기 오류 확인·UTF8_STRING 복사와 KWin 연결 검사, 확장 시험을 추가한 후 실행했다.

```sh
cargo fmt --all
cargo test --workspace --locked > docs/experiments/artifacts/2026-11-03-01/test-final.log 2>&1
cargo clippy --workspace --all-targets --locked -- -D warnings > docs/experiments/artifacts/2026-11-03-01/clippy-final.log 2>&1
cargo build --workspace --locked > docs/experiments/artifacts/2026-11-03-01/build-final.log 2>&1
python3 scripts/test-x11.py --xvfb /home/mark/Sources/way-toys/.artifacts/x11-tools/usr/bin/Xvfb --split-monitors --output docs/experiments/artifacts/2026-11-03-06 > docs/experiments/artifacts/2026-11-03-01/integration-sixth.log 2>&1
```

당시 단위 테스트 102개와 Clippy·빌드는 통과했다. 실제 Shift 배치도 성공했으나 Esc 후 원래 창 geometry로 돌아오는 assertion이 실패했다. [실패 로그](artifacts/2026-11-03-01/integration-sixth.log)와 [부분 결과](artifacts/2026-11-03-06/results.json)를 보존한다. 시험은 이 지점에서 멈췄고 뒤의 기록 창·잠금·재시작·두 화면 항목은 미실행이다.
