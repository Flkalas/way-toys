## 목적과 이전 대화 근거

당시 확인한 모드 타이밍은 다음과 같다. 가로·세로 비율은 정확히 3:2다.

## 저장 구조와 준비

커스텀 모드 등록은 X 서버의 수명에 묶이므로 로그인 전에 다시 등록하도록 구성했다. 현재 시스템의 `/usr/share/sddm/scripts/Xsession`이 `~/.xprofile`을 Plasma 실행 전에 읽는 것을 확인했다. 기존 `.xprofile`은 3줄이고 심볼릭 링크나 무조건 종료/exec 구문이 없었다.

현재 모니터의 EDID를 `xrandr --prop`에서 읽고 SHA-256만 [mode.json](artifacts/2026-11-03-11/mode.json)에 보존했다. 전체 EDID·장치 일련번호는 기록하지 않았다. 등록 스크립트는 출력 이름이 바뀌더라도 이 해시로 실제 대상 모니터를 확인한다. 다른 모니터만 연결되어 있으면 아무 모드도 추가하지 않는다.

설치 파일은 다음과 같다.

- `~/.local/bin/register-3to2-mode`: [보존한 등록 스크립트](artifacts/2026-11-03-11/register-3to2-mode.py)와 바이트가 같다. X11에서 해당 모니터에 모드를 등록하기만 한다.
- `~/.config/display-modes/3to2.json`: EDID 해시·모드 이름·타이밍 설정, 권한 0600.
- `~/.xprofile`: 기존 내용을 유지하고 등록 스크립트를 부르는 관리 블록 하나를 추가했다. 실패하더라도 로그인은 계속한다.
- KDE의 `~/.local/share/kscreen`: 선택 모드와 기존 화면 배치를 저장한다. 다음 로그인에서 이미 등록된 커스텀 모드를 복원한다.

관리 블록의 로그는 `~/.local/state/display-modes/3to2-login.log`에 누적한다. 별도 상주 프로세스나 예약 작업은 추가하지 않았다.

## 실제 명령·인수·순서

작업 디렉터리는 저장소 루트다. 실행 과정은 [설치 스크립트](artifacts/2026-11-03-11/apply-persistent-mode.py), [검증 스크립트](artifacts/2026-11-03-11/verify-persistence.py), [실제 내부 명령 목록](artifacts/2026-11-03-11/commands.jsonl)에 보존했다.

```sh
python3 docs/experiments/artifacts/2026-11-03-11/apply-persistent-mode.py > docs/experiments/artifacts/2026-11-03-11/apply.log 2>&1
python3 docs/experiments/artifacts/2026-11-03-11/verify-persistence.py > docs/experiments/artifacts/2026-11-03-11/verify.log 2>&1
```

첫 명령은 사용자 파일과 KScreen 디렉터리를 먼저 백업하고 등록 스크립트·설정·로그인 블록을 원자적으로 설치했다. 실제 해상도 선택은 아래 명령으로 수행했다. 모드 이름은 `2544x1696_59.94_mark`로 등록하며 KScreen의 약 60Hz 선택식으로 찾는다.

```sh
kscreen-doctor output.DP-1-1.mode.2544x1696@60 output.DP-1-1.position.16,1440
```

KScreen 저장을 최대 8초 동안 기다렸고 등록 스크립트를 두 번 더 실행해 중복 등록이나 화면 변경이 없음을 검사했다. 설치 스크립트는 기존 관리 블록이 있으면 재설치하지 않고 중단한다. 이미 설정된 현재 환경을 재검증할 때는 등록 스크립트와 두 번째 검증 명령만 사용한다. 다른 모니터에서 그대로 설치하는 용도가 아니며 `mode.json`의 대상 해시와 타이밍이 이 장비에 맞는다.

두 번째 명령은 Python·`.xprofile` 문법과 설치 파일 일치를 확인하고 KScreen 모듈만 unload/load했다. 재로딩 후 1초 기다리고 0.5초 간격으로 세 번 해상도를 확인했다. 전체 KDE 세션 종료나 재부팅은 하지 않았다.

```sh
qdbus6 org.kde.kded6 /kded org.kde.kded6.unloadModule kscreen
qdbus6 org.kde.kded6 /kded org.kde.kded6.loadModule kscreen
```

## 백업·정리·한계

변경 전 파일은 사용자 전용 경로 `~/.local/state/display-modes/backups/20261103-194340/`에 보존했다. 원래 `.xprofile`, 전체 KScreen 설정과 이전 해상도로 돌리는 명령 파일이 있다. 사용자 개인 설정 전체는 저장소에 복사하지 않았다. 설치한 모드·로그인 블록·KScreen 설정은 요청한 영구 설정이므로 유지한다. 임시 복구 타이머는 만들지 않았다.

실제 새 로그인·재부팅·모니터 케이블 재연결은 수행하지 않았다. 확인한 사실은 현재 출력과 저장 프로필 일치, 등록 동작의 반복 가능성, 현재 SDDM의 로그인 실행 경로, KScreen warm reload 유지다. 다음 X11 로그인에서 모드를 등록하는 것은 설치한 코드의 의도이며 실제 cold-start 검증 결과와 구분한다. EDID가 바뀌거나 다른 로그인 관리자를 쓰는 환경은 별도 확인이 필요하다.
