# 2026-11-03-01 X11 백엔드 초기 구현과 격리 환경 준비

## 목적·환경·코드

2026-11-03 KST, `/home/mark/Sources/way-toys`에서 수행했다. 기준 Git HEAD는 `47bd992`이고 X11 호환 구현의 미커밋 변경이 있었다. Debian 13.7, Linux 6.12.113+deb13-amd64, Rust/Cargo 1.99.1, KWin 6.3.6, Qt 6.8.2, Python 3.13.5, xclip 0.13, xdotool 3.20160805.1이다. Xvfb 패키지는 `2:21.1.16-1.3+deb13u4`다. Noto CJK/fontconfig를 사용했으며 글꼴 패키지의 정확한 버전은 미확인이다.

호스트는 KDE X11이지만 입력은 별도 Xvfb `1280x720x24`, KWin X11, D-Bus·XDG 디렉터리에서 실행했다. `XDG_SESSION_TYPE=x11`, `QT_QPA_PLATFORM=xcb`, `LIBGL_ALWAYS_SOFTWARE=1`, `KWIN_COMPOSE=O2`를 사용하고 `WAYLAND_DISPLAY`를 제거했다. 시험용 화면 잠금 서비스는 실제 잠금 화면이 아니다. systemd-run 래퍼는 클립보드 scope만 호스트 사용자 매니저로 연결하며 DISPLAY·XAUTHORITY는 시험 서버를 유지한다.

## 공통 준비와 격리

작업 디렉터리는 `/home/mark/Sources/way-toys`였다. 시스템에 Xvfb가 없어 다음 명령으로 패키지를 로컬 추출했다. `sudo -n true`는 암호가 필요해 실패했으며 시스템 패키지를 설치하지 않았다.

```sh
mkdir -p .artifacts/x11-tools docs/experiments/artifacts/2026-11-03-01
cd .artifacts/x11-tools
apt-get download xvfb xserver-common > download.log 2>&1
for package in ./*.deb; do dpkg-deb -x "$package" .; done
ldd usr/bin/Xvfb
```

그 뒤 작업 디렉터리를 저장소 루트로 되돌렸다. [다운로드 로그](artifacts/2026-11-03-01/xvfb-download.log)와 [도구 버전](artifacts/2026-11-03-01/tool-versions.log)을 보존한다. `xauth`, `xdotool`, `xrandr`, `xdpyinfo`, `qdbus6`, `kwin_x11`, `xclip`, systemd 사용자 매니저, Python dbus/gi/Pillow, g++와 Qt6Widgets가 이미 있었다.

Qt 고정 입력 생산자/소비자는 아래 명령으로 빌드했다. 두 빌드는 각각 실행했으며 두 번째 fixture는 02회차 직전에 추가했다.

```sh
g++ -Wall -Wextra -Werror scripts/paste-probe.cpp -o target/paste-probe $(pkg-config --cflags --libs Qt6Widgets)
g++ -Wall -Wextra -Werror scripts/capture-paste-probe.cpp -o target/capture-probe $(pkg-config --cflags --libs Qt6Widgets)
```

공통 시험 도구는 [scripts/test-x11.py](../../scripts/test-x11.py), 잠금 상태 fixture는 [scripts/x11-session-fixture.py](../../scripts/x11-session-fixture.py)다. 임시 디렉터리 아래 인증 쿠키·XDG 설정·레이아웃·DB를 만들고 빈 번호의 X 서버를 시작한다. 캡처·붙여넣기 입력은 공개 fixture만 사용한다. 인증 쿠키를 로그에 남기지 않는다. 시험 종료 시 자식 프로세스, 별도 버스, X 서버와 임시 디렉터리를 정리한다. 클립보드 소유자도 X 서버 연결 종료 후 끝난다. 사용자 단축키·실제 클립보드·실제 창에는 입력하지 않는다.

이후 재현에 시스템 Xvfb가 있으면 `--xvfb /usr/bin/Xvfb`로 바꿀 수 있다. 아래와 각 회차에 적은 `.artifacts/x11-tools/usr/bin/Xvfb` 경로는 당시 사용한 로컬 추출 파일이다. 현재 재현 절차와 지원 범위는 [X11 사용 안내](../x11.ko.md)에 있다. 각 회차에 복사한 `test-x11.py`는 당시 절차 보존용이며, 그 내용을 저장소의 `scripts/test-x11.py` 위치에서 실행해야 상대 경로가 맞는다.

## 실제 실행 순서

저장소 루트에서 다음을 순서대로 실행했다. 첫 fetch 로그는 당시 `/tmp`에서 작성한 뒤 이 폴더로 복사했다.

```sh
cargo fetch > /tmp/waytoys-x11-fetch.log 2>&1
cargo check -p waytoys-desktop -p waytoys-capture -p waytoys-paste > docs/experiments/artifacts/2026-11-03-01/check-first.log 2>&1
cargo check --workspace > docs/experiments/artifacts/2026-11-03-01/check-second.log 2>&1
cargo check --workspace > docs/experiments/artifacts/2026-11-03-01/check-third.log 2>&1
cargo fmt --all
cargo build --workspace --locked > docs/experiments/artifacts/2026-11-03-01/build-first.log 2>&1
python3 scripts/test-x11.py --xvfb /home/mark/Sources/way-toys/.artifacts/x11-tools/usr/bin/Xvfb --output docs/experiments/artifacts/2026-11-03-01/integration-first > docs/experiments/artifacts/2026-11-03-01/integration-first.log 2>&1
```

## 기대와 관찰

기대는 X11 창 실행부터 저장·복사까지의 확인이었다. 최초 검사에서 이미지 바이트 순서 타입 불일치, 다음 검사에서 공유 오류 타입 변환이 실패했고 수정 후 `check-third.log`와 workspace build는 통과했다.

최초 통합 시험은 Grid 창을 열었으나 Pillow 화면 수집이 호스트 XAUTHORITY를 참조하여 `X connection failed: error 1`로 실패했다. 이 회차를 제품 전체 성공으로 분류하지 않는다. [통합 로그](artifacts/2026-11-03-01/integration-first.log), [KWin 로그](artifacts/2026-11-03-01/integration-first/kwin.log)와 부분 결과를 보존했다.
