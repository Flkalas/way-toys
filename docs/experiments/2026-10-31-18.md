# 2026-10-31-18 FancyZones 설정 UI 항목 조사

## 목적·기준

2026-10-31 KST, 전체 원본 설정 UI를 그대로 이식하기 전에 사용자가 필요한 항목을 고를 수 있도록 실제 화면 항목을 조사했다. 결과는 [설정 UI 목록](../fancyzones-settings-inventory.ko.md)에 있다. PowerToys 기준은 기존 참고 clone의 `8827f848fbbac4afeedcae2907c71cd05fd5aa86`이며 최신 원격 HEAD를 의미하지 않는다. Waytoys는 develop `c02799b7bfb7f86a04fa85da0d5ad142f1000b9b` 위의 기존 미커밋 상태다.

Windows PowerShell 7, 작업 디렉터리 `D:\Github\utils\way-toys`에서 소스를 읽었다. VM·데스크톱 세션·원본 PowerToys 프로그램은 실행하거나 변경하지 않았다. 설정 채택이나 설정 UI 구현은 하지 않았다.

## 실제 소스 확보와 확인

기존 sparse clone에는 편집기와 런타임 소스가 있고 메인 설정 화면은 체크아웃되어 있지 않았다. 원본 트리는 수정하지 않고 다음 Git blob을 읽어 `.artifacts/settings-inventory/`에 저장했다. Git의 필요한 객체 다운로드는 허용했고 자격 증명은 출력하지 않았다.

```powershell
$refRoot = 'D:/Github/utils/way-toys/.artifacts/references/PowerToys'
$pin = git -C $refRoot rev-parse HEAD
$inventoryDir = 'D:/Github/utils/way-toys/.artifacts/settings-inventory'
New-Item -ItemType Directory -Path $inventoryDir -Force | Out-Null
$paths = @(
  'src/settings-ui/Settings.UI/SettingsXAML/Views/FancyZonesPage.xaml',
  'src/settings-ui/Settings.UI/ViewModels/FancyZonesViewModel.cs',
  'src/settings-ui/Settings.UI/Strings/en-us/Resources.resw'
)
foreach ($path in $paths) {
  $text = git -C $refRoot show "${pin}:$path"
  if ($LASTEXITCODE -ne 0) { throw "Cannot read $path" }
  $text | Set-Content -Encoding utf8 (Join-Path $inventoryDir ([IO.Path]::GetFileName($path)))
}
```

XAML 407줄, ViewModel 1134줄, 영문 리소스 6946줄을 확보했다. 실제 XAML 바인딩과 리소스 문자열을 연결하고 코드의 값·표시 조건을 대조했다.

```powershell
$page = '.artifacts/settings-inventory/FancyZonesPage.xaml'
$bindingLines = Select-String -LiteralPath $page -Pattern 'x:Bind.*Mode=TwoWay'
$bindings = @($bindingLines | ForEach-Object {
  if ($_.Line -match 'ViewModel\.([A-Za-z0-9_]+)') {
    [pscustomobject]@{ line = $_.LineNumber; property = $matches[1] }
  }
})
$bindings.Count
($bindings.property | Sort-Object -Unique).Count
```

메인 설정과 WPF 편집기를 나눠 읽기 전용으로 조사하고 원본을 교차 확인했다. 관련 후보 파일은 실제 발췌로 선별했고, 관련도가 낮다는 이유만으로 MainWindow.xaml을 제외하지 않았다. 원본 참고 clone의 `git status --short` 결과는 비어 있었다.

## 결과와 한계

- 메인 설정의 TwoWay 바인딩과 고유 속성은 각각 43개였다. 공통 기능 활성화 1개와 모듈 설정 42개다. 편집기 실행·미리보기·도움말은 설정값과 분리했다.
- 별도 편집기에서 모니터/레이아웃 선택, 이름/유형, 개수, 간격, 강조 거리, 단축키 숫자, 가로/세로 기본 레이아웃을 확인했다. Grid/Canvas의 조작은 설정 스위치와 구분했다.
- ViewModel enum에 이름이 세 개만 남아 있어도 실제 겹침 ComboBox와 Settings.h에는 네 번째 ClosestCenter가 있다. 실제 표시 옵션 네 개를 목록에 반영했다.
- Windows 11 전용 모서리 설정과 시스템 색상·Snap 단축키·동일 DPI 제약을 식별했다. KDE에서 같은 기능이 제공된다는 뜻은 아니다.
- 최초 PowerShell XPath 호출은 namespace 인수 타입이 잘못되어 실패했다. namespace 접두사 대신 `local-name()`으로 Uid 속성을 찾아 리소스 문자열을 확인했다. 이 실패는 원본 XML의 오류가 아니다.
- GitHub 웹 페이지 읽기는 캐시 오류가 있었지만 원본 Git blob을 정상 읽었다. Microsoft Learn 공식 문서도 비교했으며 정확한 목록과 개수는 고정 커밋 소스를 기준으로 했다.

한국어 항목명은 영문 리소스의 의미를 요약했다. 실제 Windows UI의 실행/접근성/각 조건 조합은 시험하지 않았고, 코드 변경 없는 정적 조사라 빌드·테스트를 실행하지 않았다. 기존 Rust 설정 모델에 값이 있다는 사실을 UI 구현 완료로 취급하지 않았다. 커밋·푸시는 하지 않았다.
