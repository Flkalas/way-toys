## 설정·트레이·로그인

- `autostart.log`: 새 로그인에서 MainPID가 생기고 ready=true, **NRestarts=0**. 이전 회차의 트레이 watcher 시작 순서 문제를 수정했다.
- `autostart-disabled-login.log`: 로그인 실행을 UI에서 끈 뒤 새 로그인 시 두 실행기 unit 모두 MainPID=0. Zones 사용 값은 true로 보존됐다.
- `ui-starts-runtime.log`, `ui-close-preserves-runtime.log`: 설정 창만 실행하여 실행기가 별도 cgroup에 생겼다. 실제 닫기 버튼으로 설정 창을 종료한 뒤 설정 창 PID=0, 실행기는 같은 PID로 active였다.
- `idle-and-single-instance.log`: 호환 이름 `waytoys-zones-settings`를 두 번 실행해도 같은 KWin 창 ID 하나가 유지됐다.
- `tray-2.log`: 실제 StatusNotifierItem Activate와 DBusMenu의 ‘Waytoys 종료’를 호출했다. 기존 설정 창이 재사용됐고 종료 후 두 MainPID=0, 저장된 사용 값은 유지됐다. 이 항목은 트레이 프로토콜 시험이며 마우스로 트레이 메뉴를 누른 시험으로 기록하지 않는다.
- `global-storage.log`: 일반 `settings.json`을 테스트용으로 손상시킨 채 실행했다. blocked=true, 활성화 요청 거절, 손상 원문 유지, 원본 복구·Reload 후 ready=true를 확인했다. 재현은 격리 경로를 검사하는 `scripts/test-runtime-storage.py`다.

## GUI·기존 편집기·캡처

실제 입력으로 Zones·모든 모니터·투명화·번호 체크박스, 숫자 10000/68, HEX `#33aa77`, 제외 앱 텍스트를 조작했다. 이전 회차에서 검증한 선택 목록·미완성 입력 보존을 유지한다. 입력 파일과 저장된 값은 23/24회차의 `*-input.json`, `edited-preferences.log`, `color-editor.log`에 있다.

창을 100% 화면으로 옮기고 KWin Resize 동작을 시작한 뒤 원격 포인터·Enter로 최소 크기까지 줄였다. `minimum-geometry.log`와 `minimum/clipboard.png`는 frame 562×329, 한글·닫기 버튼·스크롤을 확인한다. 단순 테두리 드래그 두 번은 크기가 변하지 않아 성공으로 기록하지 않았다. KWin의 `Window Resize` 액션을 시작점으로 쓴 것을 입력 파일과 명령에 구분했다. 이후 115% 화면으로 이동·확대하여 `appearance/clipboard.png`에서 입력 폼과 미리보기를 확인했다.

`existing-editor/clipboard.png`는 설정 창 버튼이 기존 전체 화면 Grid 에디터를 실행한 모습이다. 프로세스 인수는 동일 Zones 경로와 `--output Virtual-1`이었다. 번호 표시를 꺼도 `541×448`, `259×448` 치수는 유지되며, 열려 있던 에디터가 설정을 다시 읽었다(`editor-hot-reload/clipboard.png`). 번호를 복구하고 Cancel로 편집기를 닫았다. 영역 구조를 변경하거나 저장하지 않았다.

드래그 중에는 포커스를 바꾸지 않는 새 캡처 경로를 검증했다.


내부 명령은 `spectacle --background --fullscreen --nonotify --output screen.png`다. **클립보드 복사와 달리 파일 저장은 성공**했다. `runtime-native/screen.png`는 새 3922×1252 PNG이며 같은 시점의 `window.json`은 move=true, opacity=0.4를 보인다. 녹색 강조, 두 화면의 영역, 패널을 포함한 영역 크기를 확인했다. ## 측정과 정리

디버그 빌드, 해당 VM의 `/proc`을 `scripts/measure-zones-processes.py`로 관측했다. 각 구간은 5초이며 CPU는 한 프로세스가 사용한 누적 CPU 시간 차이다. 지속적인 고속 이동이나 여러 앱 부하의 벤치마크는 아니다.

| 상태 | 실행기 RSS / PSS (KiB) | 5초 CPU |
|---|---:|---:|
| 활성화 후 첫 유휴 | 12100 / 10358 | 0.02초 |
| Zones 비활성화 | 12292 / 10360 | 0.01초 |
| 두 화면 오버레이 표시 중, 포인터 정지 | 37096 / 32572 | 0.02초 |
| 표시 종료 후 | 32664 / 30734 | 0.03초 |

설정 창은 초기 유휴 RSS 107744 / PSS 103433 KiB, 5초 CPU 0.32초였다. 큰 창과 편집기 관측 중에는 RSS 109868 KiB, 5초 CPU 0.46초였다. 오버레이 객체를 해제해도 allocator가 메모리를 OS에 즉시 반환하지 않아 표시 후 RSS가 초기값까지 내려가지는 않았다. 초기 `visible-memory.log`는 편집기가 아직 열려 실제 드래그가 시작되지 않은 샘플이므로 런타임 표시 성능 근거로 사용하지 않는다. 유효 샘플은 `overlay-memory.log`다.

`cleanup.log`와 `tray-2.log`에서 종료 후 실행기·설정 창 MainPID=0, KWin attached=false를 확인했다. 편집기와 일회성 probe는 정리했다. 최종 확인용으로 설정 창과 실행기를 다시 열어 두며, 개발 경로에서만 Zones=true, 로그인 실행=false 상태를 유지한다.

두 모니터 레이아웃 SHA-256은 전후 동일하다.

```text

Virtual-2 317cce4fb914f530fda6378767dc2fc0af11ada820cd6c9f9066e15d2626cde6
```

키보드 영역 이동, 자동 편집기 화면 선택, 빠른 레이아웃 전환, 전역 단축키 등록은 이번 구현 범위 밖이며 UI에 미적용으로 표시한다. 검증 결과는 이 KWin 버전·VM 환경에 한정한다.

## 최종 확인 화면

`delivery/screen.png`에는 통합 설정의 Zones 실행 상태, 외형 입력, Canvas 미리보기와 저장 완료 상태를 캡처했다. 마지막 캡처 시 유휴 자동 잠금으로 KWin CaptureScreen이 응답하지 않았다. `loginctl show-session`의 LockedHint=yes를 확인하고 개발 VM 세션을 해제한 뒤 같은 네이티브 파일 캡처가 성공했다. 이전 클립보드 이미지를 성공한 새 캡처로 사용하지 않았다.
