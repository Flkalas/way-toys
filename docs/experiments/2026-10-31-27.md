# 2026-10-31-27 텍스트·이미지 클립보드 기록과 고정

## 결과와 범위

`waytoys-paste`를 추가하고 사용자가 선택한 **Meta+V**를 KDE에 등록했다. 텍스트·PNG/JPEG 기록, 검색·종류 필터·페이지 이동, 재복사, 고정·고정 해제·개별 삭제·고정 제외 기록 정리를 제공한다. 통합 설정의 클립보드 페이지와 트레이에 연결했다. Meta+Shift+S로 캡처한 PNG도 수집한다. 선택하면 복사하고 창을 닫으며 실제 붙여넣기는 사용자가 Ctrl+V로 한다.

최종 워크스페이스 테스트 **101개**, fmt, Clippy `--all-targets -- -D warnings`, 빌드가 통과했다. VM에서 실제 키·포인터 입력과 Qt 붙여넣기 소비자로 한글·줄바꿈·이미지 픽셀을 검증했다. 고정 항목은 실행기 재시작과 최근 기록 정리 후에도 남았다. 일반 설정에는 `enabled.paste=true`만 추가하고 Zones 설정·모니터별 레이아웃·kwinrc는 보존했다.

## 구현

수집기는 Wayland wlr data-control을 통해 일반 클립보드의 MIME offer를 읽는다. primary selection은 제외한다. PNG, JPEG, UTF-8 텍스트 순으로 선택하며 암호 관리자가 민감 형식으로 표시한 offer는 읽지 않는다. 활성화·잠금·정리 시 epoch를 바꿔 진행 중인 오래된 입력이 다시 저장되지 않게 한다. 화면 잠금 상태를 알 수 없을 때는 수집·목록·복사를 허용하지 않는다.

SQLite를 수집기 하나에서 열고 원문, MIME, 픽셀 기반 이미지 해시, 작은 RGBA thumbnail, 고정 상태와 순서를 트랜잭션으로 저장한다. WAL·FULL synchronous·secure_delete를 사용한다. 삭제/정리 뒤 WAL을 truncate한다. 알려지지 않은 DB 버전이나 손상 파일은 덮어쓰지 않는다. 다시 읽기 경로가 있다. 디렉터리 0700, DB 0600을 적용한다.

일반 기록은 100개·원본 64 MiB, 고정 기록은 별도 100개·128 MiB다. 고정 한도 초과는 오류로 표시하며 기존 고정을 지우지 않는다. 텍스트는 1 MiB, 이미지는 인코딩 데이터 16 MiB·24메가픽셀로 제한하고 디코더 메모리에도 상한을 둔다. 이 한도는 DB 파일 전체나 프로세스 RSS의 상한이라는 뜻이 아니다.

기록 창은 Iced 0.14.0, tiny-skia, Wayland, thread-pool, image-without-codecs와 Noto Sans CJK KR을 사용한다. 한 페이지는 12개이며 보이는 항목의 thumbnail만 가져와 캐시한다. 닫으면 UI 프로세스가 종료된다. 실행기가 수집기를 관리하고 설정의 `enabled.paste`를 전달한다. DB 경로는 기본 XDG 데이터 디렉터리, 명시한 앱 설정 경로 아래 `paste`, 또는 `--paste-data-dir` 순서로 결정한다. 기존 설정에 새 필드가 없으면 false로 읽는다.

클립보드로 다시 복사할 때는 원문 바이트와 MIME을 별도 사용자 scope의 `wl-copy`로 전달한다. 실행기 종료 후에도 현재 클립보드 데이터는 남고 다음 복사 때 소유자가 교체된다. 캡처 선택 중에는 기록 창을 새로 열지 않는다. 기록 창 표시 중에는 Zones 연결을 일시 정지하고 닫힌 뒤 복구한다.

## 발견한 실패와 수정

- 최초 thumbnail 테스트가 작은 이미지를 128×64로 확대한 것을 발견했다. 원본 크기와 최대 128×80 중 작은 값을 사용하도록 수정했다(`build-first.log`).
- Clippy의 불필요한 소유 `PathBuf` 비교를 `Path::new` 비교로 고쳤다(`build-second.log`).
- 101개 테스트와 Clippy 이후 링크 중 VM 디스크가 가득 찼다(`build-final.log`). 경로를 검증한 `cleanup-build-cache.py`로 **이 저장소의 `target/debug/incremental`만** 제거하고 `CARGO_INCREMENTAL=0`으로 재빌드했다(`build-recovered.log`). 설정·DB·레이아웃이나 다른 작업 디렉터리는 삭제하지 않았다.
- 고정 해제 버튼의 한글 줄바꿈을 글자 크기 13으로 수정했다(`build-ui-final.log`). XDG 경로가 주어져도 eager fallback에서 HOME을 요구하던 코드를 지연 분기로 바꾸고 최종 전체 검사에 포함했다(`build-xdg-final.log`). `verify.sh`는 HOME이 없는 XDG 환경에서 읽기 전용 `--status`도 확인한다.
- 최초 일시 중지 테스트는 시험용 `wl-copy` 자식이 SSH 출력 파이프를 유지해 30초 timeout이 났다(`pause-capture.log`). 시험 producer의 출력만 `/dev/null`로 돌려 수정했다. 제품 복사 경로는 처음부터 별도 systemd scope와 제한 시간을 사용한다.
- 창 테두리 1픽셀 좌표가 resize로 인식되지 않았고 VM의 Alt+F8도 등록되어 있지 않았다(`delivery.log`, `delivery-final.log`). 확인된 KWin `Window Resize` 동작을 D-Bus로 시작한 뒤 QMP 방향키로 크기를 조절했다.
- 높이가 다른 출력 사이에서 낮은 위치로 곧바로 절대 좌표 이동하면 포인터가 첫 출력 모서리 847,479에 머물렀다. 이 때문에 초기 정리 버튼 시험이 바탕화면 버튼을 눌렀다(`delivery-final2`, `layout-clear-final`). 두 출력에 공통으로 존재하는 y=250을 거쳐 이동하도록 입력 도구를 보정했다. 이후 확인 버튼 좌표도 실제 캡처로 교정했다(`clear-measure-final` → `clear-measure-passed`). 초기 페이지 시험의 ‘아무 fixture 문자열’ 판정도 두 번째 페이지의 정확한 항목 비교로 강화했다. 최종 합격 근거는 `layout-paging-passed`다.

## 측정·화면·보존

`clear-measure-passed/memory.json`은 115% 화면에서 기록 17개 중 첫 페이지를 표시한 디버그 빌드를 3.000초 관찰한 값이다. `/proc`와 D-Bus 소유자 PID로 측정했으며 메모리 값은 구간 끝의 값이다.

| 프로세스 | RSS KiB | PSS KiB | threads | 구간 CPU 초 |
|---|---:|---:|---:|---:|
| 공통 실행기 | 12,528 | 10,684 | 7 | 0.02 |
| 클립보드 수집기 | 17,032 | 14,903 | 6 | 0.00 |
| 기록 UI | 109,260 | 102,977 | 9 | 0.07 |

UI PID 96545는 창을 닫은 뒤 사라졌다. CPU 0.00은 해당 짧은 구간에서 tick 변화가 없었다는 뜻이며 항상 CPU를 쓰지 않는다는 주장이 아니다. 이미지가 많은 장시간 기록, 콜드 스타트, release 빌드나 다른 해상도의 성능으로 일반화하지 않는다. 종료 후 현재 클립보드를 제공하는 `wl-copy`가 남는 것은 의도한 수명이다.

`final-screen`은 마지막 설정 페이지와 고정 항목을 실제 VM에서 캡처한 결과다. Orca 탭 메타데이터는 `clipboard-tab.json`, `settings-tab.json`, `browser-tabs.json`에 보존한다. 검증 캡처는 Spectacle background 파일 출력이며 클립보드를 수정하지 않는다.

마지막 실행은 `restart-final.sh`로 유효값을 저장하며 기존 설정 창·실행기를 닫고 최종 빌드를 `waytoys-settings-27-final.service`에서 시작했다. 설정은 같은 개발 경로를 사용한다. `final_screen`은 fixture를 띄우지 않으며 실제 Meta+V 열기·닫기를 확인한 뒤 설정 창만 남긴다.

`verify.sh`/`verify.log`는 기존 preferences·두 layout·kwinrc 해시, 앱 설정의 변경 범위, DB 권한·quick_check·고정 개수, 실행기·수집기 준비 상태와 종료된 picker/capture 소유자를 확인한다. 최종 Python AST·shell 문법·git diff 공백 검사는 `static-check.log`에 기록한다. `source-manifest.json`과 게스트 해시 비교는 로컬/VM 소스 동기화 확인에 사용한다.

최종 소스 동기화 뒤 저장소 루트에서 `python3.13 docs/experiments/artifacts/2026-10-31-27/verify-source.py`를 실행했다. 85개 파일의 바이트 SHA-256이 로컬과 게스트에서 일치했다.

검증 범위는 이 KWin 6.3.6 Wayland VM의 디버그 빌드다. PNG의 실제 앱 붙여넣기는 검증했지만 JPEG를 제공하는 별도 앱의 end-to-end 시험, 재로그인 후 Meta+V, Windows PVE 브라우저를 통한 Meta+V 전달, 장기간·대형 이미지 부하 시험은 하지 않았다. Windows 호스트가 Meta+V를 먼저 처리하면 VM 설정의 기록 열기 버튼이나 트레이를 사용할 수 있다.
