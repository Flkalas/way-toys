# 2026-10-31-23 KWin Shift 드래그 연결

## 범위와 환경

Windows 작업 폴더 `D:\Github\utils\way-toys`, VM 700의 Debian/KWin 6.3.6 Wayland에서 기존 오버레이 편집기를 유지하고 실제 창 배치 연결을 구현한다. 기준 HEAD는 `c02799b7bfb7f86a04fa85da0d5ad142f1000b9b`이며 앞선 미커밋 작업은 보존한다. 통합 일반 설정 창은 기존 오버레이 존 편집기를 실행한다.

개발 의존성은 다음 명령으로 설치했다. [설치 로그](artifacts/2026-10-31-23/dependencies.log).

```powershell
ssh debian@192.168.50.125 'sudo -n apt-get install -y kwin-dev qt6-base-dev extra-cmake-modules cmake ninja-build'
```

게스트의 `/home/debian/projects/way-toys`에서 다음으로 빌드했다.

```bash
cmake -S kwin/zones -B target/kwin-zones -G Ninja -DCMAKE_BUILD_TYPE=Debug
cmake --build target/kwin-zones
```

첫 CMake 구성은 KWin 패키지의 Qt6::Widgets 전이 의존성 미선언으로 실패하여 Widgets를 명시했다. 첫 C++ 빌드는 보호 멤버 접근 한 곳에서 실패하여 공개 move/resize 조회 API로 수정했다. 세 번째 빌드는 `-Wall -Wextra -Werror`로 통과했다. 각 로그는 같은 artifact 디렉터리에 보존했다.

Debian 13.7, Linux 6.12.113+deb13-amd64, KWin 패키지 `4:6.3.6-1`, Rust/Cargo 1.99.1, 2 CPU·8 GiB VM에서 수행했다. 화면은 Virtual-1 848×480·100%, Virtual-2 1280×720·115%다. KWin이 보고한 두 번째 화면의 전역 논리 사각형은 `[848,0,1113,626]`이다. Wayland/KScreen의 반올림된 크기 표기와 섞지 않고 KWin 좌표로 배치했다.

## 실행과 결과

테스트 앱용 `konsole xterm python3-gi`도 설치했다. 최초 Python probe는 `gi` 부재로 실패했고 설치 후 재실행했다. `scripts/kwin-bridge-poc.py`를 `waytoys-bridge-probe` 사용자 unit으로 실행하고 `scripts/zones-settings-vm.ps1 -Action Input -Events docs/experiments/artifacts/2026-10-31-23/probe-shift-drag.json`으로 Shift 드래그했다. `probe-drag.log`와 `probe-after/clipboard.png`에서 KWin 배치 요청 `[864,16,400,594]` 수락과 해당 창의 이동을 확인했다. 이 임시 probe는 종료했다.

격리 경로는 `/home/debian/waytoys-test-results/settings-23/app`과 `zones`다. Zones 디렉터리는 22회차 설정을 복사했으며 실제 XDG의 기존 레이아웃 파일은 수정하지 않았다. 일반 설정은 처음 없었고 두 플래그가 false였다. `waytoys-runtime-23`, `waytoys-settings-23`, `waytoys-probe-window`라는 사용자 unit으로 실행했다. 실행 명령은 `runtime-start.log`, `update-start.log`, 입력은 같은 디렉터리의 `*-input.json`에 보존했다.

- GUI의 Zones 체크박스는 `settings.json`의 `enabled.zones=true`를 저장하고 `ready=true`가 됐다.
- GUI에서 제외 목록을 비우고 투명화를 켰다. 표시 시간을 실제 키 입력으로 10000ms로 바꾸었다.
- 제외 상태의 Konsole는 KDE 기본 타일 `[638,4,206,432]`로 배치됐다. 제외를 해제한 동일 드롭은 Waytoys 레이아웃의 `[573,16,259,448]`로 배치됐다. `excluded-result.log`, `owned-after.log`에 실제 KWin 사각형이 있다.
- 원래 opacity 0.8이 드래그 중 0.4가 되고 드롭 후 0.8로 복구됐다. `owned-during.log`, `owned-after.log` 참조.
- `python3.13 scripts/test-zones-runtime.py --output docs/experiments/artifacts/2026-10-31-23/integration-2`와 후속 `--only excluded_case,corrupt_preferences,screen_lock` 시험에서 중간 Shift, Ctrl 합집합, 화면 이동, Shift 해제, Esc, 모듈 중지, heartbeat 만료, 실행기 강제 종료, 제외 대소문자, 손상 파일, 화면 잠금을 확인했다. 최종 코드 전체 재시험은 [24회차](2026-10-31-24.md)다.

## 실패·수정과 증거 한계

첫 `--locked` 검증은 새 의존성의 lock 갱신 필요로 실패했다. 오프라인으로 lock을 갱신하고 이후 `--locked` 빌드·테스트·Clippy를 통과했다. `rust-validation-2.log`, `final-build.log`, `validated-build.log`에 보존했다.

화면 이동 시험은 처음 포인터가 QEMU/KWin 화면 경계에 멈춰 영역 바깥에 드롭하여 실패했다. D-Bus 기록 `cross-trace.log`는 요청한 X=1000 대신 실제 X=849.95를 보여준다. QEMU가 동일한 절대 좌표 입력을 생략하므로 테스트 입력에 서로 다른 두 좌표를 사용해 실제 통과를 확인했다. 제품의 영역 계산을 변경하여 테스트를 맞추지 않았다.

Windows의 Python text stdin이 CRLF를 전달하여 멀티라인 bash fixture가 실패했다. 이후 UTF-8 바이트로 전달한다. `integration-2.log`에 실패, `integration-3.log`에 수정 후 결과가 있다.

SDDM 단순 restart는 이전 세션 정지와 다음 세션 시작이 겹쳐 Plasma systemd transaction이 실패했다. stop 완료 후 start로 분리했다. 첫 자동 로그인은 트레이 watcher가 늦게 생겨 실행기가 1회 재시작한 뒤 준비됐다. ksni의 watcher 대기 기능으로 수정했고 24회차 새 로그인에서는 재시작 0회였다.

드래그 중 Spectacle GUI의 Ctrl+C는 실제 드래그 입력과 충돌했다. `owned-during/clipboard.png`는 이전 클립보드 화면이므로 **실시간 오버레이 증거로 사용하지 않는다**. QMP 캡처는 화면 외 QXL 버퍼에 오래된 픽셀이 남는 한계가 있다. 24회차에서는 Spectacle의 백그라운드 파일 저장으로 포커스와 입력을 바꾸지 않고 새 PNG를 수집했다.

일반 로그인 실행 등록과 새 로그인 성공은 `autostart-before-login.log`, `autostart-after-login.log`에 있다. 이 회차에서 설정 창과 실행기를 따로 시작한 시험만으로는 설정 창에서 처음 띄운 실행기의 수명을 검증한 것이 아니므로, 별도 사용자 서비스 시작 경로를 구현하고 24회차에 독립적으로 확인했다.
