# 2026-10-31-26 이미지 영역 캡처와 Meta+Shift+S

## 결과와 범위

`waytoys-capture`를 추가하고 KDE 단축키, 트레이, 통합 설정 창에 연결했다. 화면을 드래그하고 놓으면 PNG 이미지가 클립보드에 들어간다. Esc·오른쪽 클릭은 취소한다. 동영상·주석·파일 저장 UI·캡처 설정 파일은 추가하지 않았다. 사용자 선택에 따라 Meta+Shift+S를 등록하고 Spectacle의 PrintScreen은 유지했다.

최종 워크스페이스 테스트 **95개**, fmt, Clippy `-D warnings`, 빌드가 통과했다. 실제 VM 키·포인터 입력으로 붙여넣기와 화면별 배율·취소를 확인했다. 일반 설정·Zones 설정·두 모니터 레이아웃·kwinrc는 시작 전과 동일하다. 실제 선택 화면과 설정 화면을 Orca 탭에 열었다.

## 발견한 실패와 수정

- 최초 KGlobalAccel `setShortcut`의 flags=4는 저장은 됐지만 `isActive=false`여서 실제 키 입력이 실행하지 못했다. `SetPresent | NoAutoloading`인 flags=6으로 수정한 뒤 실제 Meta+Shift+S 입력이 통과했다(`hotkey-input.json`, `shortcut-fix.log`).
- 런타임 API의 잘못된 `/Runtime` 경로를 기존 계약 `/Waytoys`로 수정했다. 최종 시험은 해당 경로로 Zones 일시 정지·복구를 확인했다.
- 잠금 해제 직후 PNG 바이트 해시를 비교한 첫 추가 시험은 실패했다(`failures`). KDE/Klipper가 소유권을 인계받고 PNG를 다시 인코딩할 수 있으며, 잠금 해제 후 실제 포인터 이벤트와 ScreenSaver 비활성 확인도 필요했다. 수정 시험은 디코딩한 RGBA 픽셀을 비교했다. 실행기 종료 수명 검사는 잠금과 분리하여 새 캡처·새 wl-copy scope로 확인했다.
- 설정 창 최소화 후 복원 시험이 실패했다(`delivery`). Winit의 Wayland 경로는 un-minimize를 지원하지 않는다([공식 API](https://docs.rs/winit/latest/winit/window/struct.Window.html#method.set_minimized)). `minimize(false)`를 반복하는 대신 유효값 저장과 실행 요청 성공 후 설정 창을 닫고 트레이에서 다시 여는 동작으로 변경했다. `delivery-final`에서 새 창 ID와 minimized=false를 확인했다. 저장 오류나 열린 편집기가 있으면 기존 닫기 보호 규칙을 따른다.
- 잠겨 있는 동안 준비했던 `settings-geometry.log`와 실패한 최초 캡처 시도는 화면 검증 근거로 사용하지 않는다. 최종 화면은 아래 파일이다.

## 화면·측정·보존

`delivery-final/selection-screen.png`는 버튼을 누른 채 유지하는 동안 Spectacle의 파일 캡처로 얻은 실제 화면이며, `selected-region.png`는 놓은 뒤 클립보드에서 읽은 원본 결과다. 검증용 화면 캡처는 클립보드를 바꾸지 않는 `scripts/capture-wayland-file.ps1` 또는 같은 Spectacle background 파일 경로로 실행했다.

두 화면을 직접 확인했고 탭 메타데이터를 `selection-tab.json`, `settings-tab.json`, `browser-tabs.json`에 보존했다. 최종 설정 창은 115% 화면에 논리 frame 900×500으로 열어 두었다. `delivery-settings-geometry.log`에서 위치와 크기를 확인했다.

`delivery-final/memory.json`: 두 화면에 선택이 정지한 상태에서 3.001초 동안 PID 77016을 측정했다. RSS **31,104 KiB**, PSS **24,000 KiB**, 샘플 중 peak RSS **31,104 KiB**, 5 threads였다. CPU 누적 tick 변화는 0이었으며 이는 해당 3초 구간에서 계측 해상도 이하였다는 뜻이다. 드래그 중 CPU, 대형 모니터, 콜드 스타트 성능으로 일반화하지 않는다. 복사 후 PID가 없음을 확인했다. 최종 클립보드 소유자 wl-copy 하나는 RSS **900 KiB**, PSS **210 KiB**였다(`verify.log`).

`verify.sh`를 게스트에서 실행하여 `before.sha256`의 다섯 파일을 재검사했고 모두 OK다. `verify.log`는 runtime ready=true / 오류 없음 / Zones=true / 로그인 실행=false, Capture1 소유자 없음, ScreenSaver 비활성을 기록한다. 최종 Python AST·shell 문법·git diff 공백 검사도 통과했다. 제품 설정 JSON에 Capture 활성화 필드나 새 파일은 생기지 않았다.

검증은 이 VM의 KWin 6.3.6 Wayland 디버그 빌드에 한정한다. 재로그인 뒤 단축키, Windows 브라우저가 PVE 콘솔로 Meta+Shift+S를 전달하는지, 회전 화면·HDR·물리 화면 핫플러그는 이번에 실측하지 않았다. Windows 호스트가 단축키를 먼저 처리하는 경우 VM의 설정·트레이 버튼으로 시작할 수 있다.
