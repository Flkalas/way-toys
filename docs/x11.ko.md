# KDE Plasma X11 사용

통합 설정 창, Grid 에디터, Zones 창 배치, 영역 캡처와 텍스트·이미지 클립보드 기록을 X11에서도 사용한다. 기존 Wayland 경로와 함께 빌드하며 별도 실행 파일로 나누지 않는다. 검증 대상은 Debian 13.7 / KWin 6.3.6이다.

## 설치와 실행

로그인한 KDE Plasma X11 사용자의 터미널에서 저장소 루트를 작업 디렉터리로 사용한다. Rust 1.99.1과 기존 Wayland/xkbcommon 개발 의존성이 필요하다. X11 연결은 Rust의 x11rb를 사용한다. 실행에는 `xclip`, fontconfig, Noto CJK와 systemd 사용자 세션이 필요하다.

```sh
sudo apt-get install xclip fonts-noto-cjk python3-dbus
cargo build --workspace --locked
./target/debug/waytoys-settings
```

Zones 페이지에서 **Zones 사용**, 클립보드 페이지에서 **클립보드 기록 수집**을 켠다. 두 값의 기본값은 꺼짐이다. X11 Zones는 실행기가 내장 KWin 스크립트를 불러오므로 `install-kwin-zones.sh`를 실행하지 않는다. Wayland의 네이티브 플러그인은 기존 설치 방법을 따른다.

캡처와 클립보드 단축키를 등록하려면 다음을 실행한다. 기존 키 충돌 검사·백업·복구 정책은 [캡처](capture.ko.md)와 [클립보드](paste.ko.md) 문서를 따른다. `kbuildsycoca6`가 필요하다.

```sh
sh scripts/install-capture.sh --shortcut
sh scripts/install-paste.sh --shortcut
```

직접 실행과 출력 확인도 가능하다.

```sh
./target/debug/waytoys-zones-editor --list-outputs --json
./target/debug/waytoys-zones-editor --output HDMI-1
./target/debug/waytoys-capture --check
./target/debug/waytoys-capture
./target/debug/waytoys --paste
```

`HDMI-1`은 실제 `--list-outputs` 결과의 이름으로 바꾼다. 개발용 설정과 기록을 분리하려면 다음처럼 실행한다.

```sh
./target/debug/waytoys-settings \
  --app-config-dir /tmp/waytoys-x11-demo/app \
  --config-dir /tmp/waytoys-x11-demo/zones \
  --paste-data-dir /tmp/waytoys-x11-demo/history
```

## 세션·좌표·지원 범위

- `XDG_SESSION_TYPE=x11`과 `DISPLAY`, 또는 `XDG_SESSION_TYPE=wayland`와 `WAYLAND_DISPLAY`를 사용한다. 세션 종류가 명시되지 않았으면 Wayland 연결 환경을 먼저 확인하고 X11을 선택한다. systemd로 시작하는 실행기에는 DISPLAY·XAUTHORITY·세션 종류도 전달한다.
- X11 화면 정보는 **XRandR 1.5 모니터** 기준이다. 좌표와 캡처는 X 서버의 루트 픽셀을 사용하며 에디터 출력 JSON의 `integer_scale`은 1이다. Wayland의 모니터별 분수 배율 개념과 다르다. 출력 이름이 다르면 레이아웃 파일도 각각 사용한다.
- Zones와 Grid 에디터의 투명 오버레이에는 **KWin 합성(Compositing)**과 32비트 TrueColor visual이 필요하다. 꺼져 있으면 오류를 표시한다. 캡처는 루트 이미지와 일반 TrueColor 창을 사용한다.
- Zones는 **KWin 스크립팅 API와 XInput 2.1**을 사용한다. Shift·Ctrl·Esc 및 왼쪽 버튼 전환만 상태로 유지하며 다른 키 내용은 저장하지 않는다. 표시 창은 입력을 통과시킨다. 드롭은 KWin 소유자·인스턴스·순번을 검사하며 150ms가 지난 응답은 적용하지 않는다.
- Shift 드래그 배치, Ctrl 합집합 선택, 제외 앱과 최소 크기 검사를 공유한다. X11의 **드래그 창 투명화는 제공하지 않으며** 설정 창에 적용 범위를 표시한다. 기본 KDE 타일 미리보기와 Waytoys 영역이 함께 보일 수 있다.
- X11 캡처는 현재 화면의 픽셀을 가져오고 모니터 경계를 넘는 영역을 합성한다. Esc·오른쪽 클릭·화면 구성 변경·잠금·종료 시 취소한다. Wayland의 KWin 화면 획득 권한 등록은 X11 직접 실행에 필요하지 않다.
- 클립보드 수집은 XFixes 변경 알림, TARGETS와 INCR을 지원하는 `xclip`을 사용한다. 재복사한 일반 텍스트는 `UTF8_STRING`으로 제공한다. 이미지·검색·고정·SQLite 저장 형식과 예산은 공통이다.
- 캡처/기록 선택 중 Zones를 일시 정지하고 종료 후 다시 연결한다. UI 종료 시 표시·입력 자원을 해제하며 현재 클립보드 소유자는 별도 사용자 scope에서 유지한다.

KWin 외 창 관리자, 다른 KWin 버전, 실제 X11 다중 모니터의 회전·변환·고해상도 조합, 장시간 부하와 재로그인 후 단축키는 이번에 검증하지 않았다. GUI 없는 레이아웃 모델·CLI와 단위 테스트는 데스크톱 세션 없이 사용할 수 있다.

## 검증과 재현

격리된 Xvfb, KWin X11, 별도 D-Bus·XDG 디렉터리에서 XTest 입력과 Qt 생산자/소비자를 사용했다. 실제 사용자 데스크톱의 창·클립보드·단축키에는 입력하지 않는다. 화면 잠금 D-Bus 서비스는 시험용이므로 실제 잠금 화면 검증으로 해석하지 않는다. 두 화면 시험은 XRandR의 합성 모니터 구성이며 물리 모니터 시험이 아니다.

시스템 Xvfb를 설치한 경우 저장소 루트에서 실행한다. 필요한 도구는 `scripts/test-x11.py`의 설명과 [준비 기록](experiments/2026-11-03-01.md)에 있다.

```sh
g++ -Wall -Wextra -Werror scripts/paste-probe.cpp -o target/paste-probe $(pkg-config --cflags --libs Qt6Widgets)
g++ -Wall -Wextra -Werror scripts/capture-paste-probe.cpp -o target/capture-probe $(pkg-config --cflags --libs Qt6Widgets)
cargo build --workspace --locked
python3 scripts/test-x11.py --xvfb /usr/bin/Xvfb --split-monitors --output .artifacts/x11-check
```

기록 창 검색·Enter 선택·Qt 붙여넣기, 캡처 픽셀 일치, Esc 보존, Shift 창 배치와 Esc 복구, 고정 복원, 실행기 종료 후 클립보드 유지 및 화면 경계 합성을 확인한다. 시험이 끝나면 자식 프로세스·별도 버스·X 서버·임시 인증과 설정을 정리하고 결과·명령·소스 해시·화면을 출력 디렉터리에 남긴다. 현재 클립보드를 제공하는 시험용 xclip은 해당 X 서버 종료로 연결을 잃고 종료한다.
