# 2026-10-31-04 X11 중첩 혼합 배율 입력 오류 재현 및 원인 분석

## 목적과 범위

기존 실험의 둘째 출력 입력이 첫째 출력으로 전달되는 결과를 재현하고 원인 계층을 확인한다. 이것은 X11 중첩 시험의 입력 오류 조사이며, 실제 DRM/Wayland 출력에서 오버레이가 합쳐지는 문제를 입증하는 실험이 아니다. 기본 VM 세션에서 이미 확인한 출력별 오버레이 표시 결과와 구분한다. 이 시험 오류를 제품 개발의 차단 조건으로 삼지 않는다.

## 환경과 재현

- 2026-10-31 KST, VM 700 Debian 13, 커널 `6.12.113+deb13-amd64`. 기본 세션은 Plasma Wayland이며 시험은 독립 Xvfb 안에서 수행했다.
- Git `c02799b7bfb7f86a04fa85da0d5ad142f1000b9b`. 기존 앱 구현은 변경하지 않았다. 신규 headless 래퍼는 미커밋 상태였다.
- Rust 1.99.1, KWin `4:6.3.6-1`, Xvfb `2:21.1.16-1.3+deb13u4`, Openbox `3.6.1-12+b2`, wmctrl `1.07+git20240228.1105759-1`, xdotool `1:3.20160805.1-5.1`, ImageMagick `8:7.1.1.43+dfsg1-1+deb13u13`.
- [headless 래퍼](../../scripts/reproduce-nested-overlay-headless.sh)가 Xvfb `3000x1600x24`와 Openbox를 생성하고, 기존 [재현 스크립트](../../scripts/reproduce-nested-overlay.sh)를 `equal`, `mixed` 순으로 호출한다. `XAUTHORITY`는 `xvfb-run`이 생성한다. 각 시험은 독립 D-Bus, Wayland 소켓과 임시 설정을 사용한다.
- 래퍼는 격리된 X 서버의 `_NET_CLIENT_LIST`에 있는 창에 누락된 `WM_CLIENT_MACHINE=localhost` 속성을 추가해 wmctrl의 크래시를 피한다. 이는 설명용 메타데이터를 보완하는 처리이며 출력 크기, 배율, 창 순서 또는 입력 좌표는 수정하지 않는다. 출력과 창 대응은 기존 스크립트의 열거 순서 한계를 그대로 가진다.

VM에서 다음과 같이 실행했다. 준비 패키지는 앞선 회차에 설치했다.

```sh
cd /home/debian/projects/way-toys
. "$HOME/.cargo/env"
sh -n scripts/reproduce-nested-overlay-headless.sh
sh scripts/reproduce-nested-overlay-headless.sh /home/debian/waytoys-test-results/2026-10-31-04
```

첫째 출력 800×600, 둘째 출력 600×400이다. `equal`은 둘 다 100%, `mixed`는 둘째만 150%다. 두 경우 모두 둘째 X11 창에서 `(150,100)`에서 `(450,300)`으로 합성 드래그하고 각 출력 이미지를 수집했다. 래퍼 종료 시 시험용 KWin/Openbox/Xvfb를 정리한다. 결과 디렉터리는 보존한다.

## 실제 결과

- `equal`: `selection output=1 x=150 y=100 width=300 height=200`.
- `mixed`: `selection output=0 x=633.33203125 y=66.6640625 width=165.66796875 height=133.3359375`.
- 혼합 배율의 `first.png`에서 첫째 출력 오른쪽에 흰 선택 테두리가 나타나고, `second.png`에는 선택 테두리가 없음을 직접 확인했다. 과거 기록과 같은 실패를 재현했다.
- 두 실행의 종료 코드 0은 로그와 이미지 수집 완료를 뜻한다. 혼합 배율 동작의 성공을 뜻하지 않는다.

## 원인 분석과 한계

[KWin 6.3.6의 X11WindowedOutput::mapFromGlobal](https://github.com/KDE/kwin/blob/v6.3.6/src/backends/x11/windowed/x11_windowed_output.cpp#L316-L319)은 `(pos - hostPosition() + internalPosition()) / scale()`로 계산한다. [포인터 모션과 버튼 처리](https://github.com/KDE/kwin/blob/v6.3.6/src/backends/x11/windowed/x11_windowed_backend.cpp#L365-L374)에서 이 변환을 사용한다.

둘째 출력의 시작 X가 800일 때, 둘째 창 안의 X=150은 이 식에서 `(150+800)/1.5 = 633.333...`이 된다. 의도한 위치는 `800 + 150/1.5 = 900`이다. 출력의 논리적 시작 위치까지 배율로 나누어 첫째 출력 범위로 들어가는 것이다. 실제 시작 로그 `x=633.33203125`, `y=66.6640625`는 이 변환 결과의 Wayland 고정소수점 값과 일치한다. 소스와 대조 실험을 함께 보면 이 중첩 실험 실패의 원인을 X11 백엔드의 좌표 변환으로 설명할 수 있다. 로그의 선택 종료 위치 전체에 대한 별도 추적은 하지 않았다.

이는 KWin의 X11 중첩 백엔드 경로다. 물리 모니터를 직접 관리하는 DRM 세션 및 VM 기본 Plasma Wayland 세션에 동일한 원인을 적용할 근거는 없다. 사용자가 별도 실제 PC에서 보고한 현상은 이 실험으로 해결되거나 원인이 확정된 것이 아니다. 제품 코드 또는 설치된 KWin 바이너리는 수정하지 않았다.
