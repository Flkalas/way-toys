# 2026-11-03-09 최종 검사에서 테스트 모듈 위치 Clippy 오류

## 목적·환경·코드

2026-11-03 KST, `/home/mark/Sources/way-toys`에서 수행했다. 기준 Git HEAD는 `47bd992`이고 X11 호환 구현의 미커밋 변경이 있었다. Debian 13.7, Linux 6.12.113+deb13-amd64, Rust/Cargo 1.99.1, KWin 6.3.6, Qt 6.8.2, Python 3.13.5, xclip 0.13, xdotool 3.20160805.1이다. Xvfb 패키지는 `2:21.1.16-1.3+deb13u4`다. 호스트는 KDE X11이지만 입력은 별도 Xvfb `1280x720x24`, KWin X11, D-Bus·XDG 디렉터리에서 실행했다. `XDG_SESSION_TYPE=x11`, `QT_QPA_PLATFORM=xcb`, `LIBGL_ALWAYS_SOFTWARE=1`, `KWIN_COMPOSE=O2`를 사용하고 `WAYLAND_DISPLAY`를 제거했다. 시험용 화면 잠금 서비스는 실제 잠금 화면이 아니다. systemd-run 래퍼는 클립보드 scope만 호스트 사용자 매니저로 연결하며 DISPLAY·XAUTHORITY는 시험 서버를 유지한다.

공통 의존성·준비·격리·정리는 [01회차](2026-11-03-01.md#공통-준비와-격리)를 따른다. 이 회차의 명령과 인수는 아래에 따로 적었다.

## 실제 실행 순서

유휴 중에도 XInput 큐를 비우는 변경 후 다음 순서의 명령을 실행했다.

```sh
cargo fmt --all
cargo test --workspace --locked > docs/experiments/artifacts/2026-11-03-09/test.log 2>&1
cargo fmt --all -- --check > docs/experiments/artifacts/2026-11-03-09/fmt.log 2>&1
cargo clippy --workspace --all-targets --locked -- -D warnings > docs/experiments/artifacts/2026-11-03-09/clippy.log 2>&1
```

실제 셸은 `&&`로 다음 workspace build와 X11 integration까지 연결했으나 Clippy 실패로 그 두 명령은 실행하지 않았다. 이 회차의 build/integration 로그가 없는 이유다.

## 기대와 관찰

단위 테스트 104개와 fmt는 통과했다. Clippy는 `crates/waytoys-runtime/src/x11.rs`의 테스트 모듈 뒤에 Drop 구현이 있다는 `items_after_test_module`을 경고했고 `-D warnings`로 실패했다. [테스트 로그](artifacts/2026-11-03-09/test.log), [Clippy 로그](artifacts/2026-11-03-09/clippy.log)를 보존한다.
