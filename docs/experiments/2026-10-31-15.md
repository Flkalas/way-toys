## 구현과 입력

`crates/waytoys-zones`에 라이브러리와 CLI를 추가했다. Grid/Canvas 모델과 사용자 레이아웃 JSON, 설정 기본값, 템플릿 계산, 구역 선택, Grid 분할·병합·경계 이동, Canvas 추가·이동·크기 조절·자석 보정과 편집 상태를 포함한다. 직접 의존성은 `serde`와 `serde_json`이다. `waytoys-core`에는 변경을 넣지 않았다.

입력은 저장소의 `crates/waytoys-zones/examples/custom-layouts.json`이다. Grid 3열(25%/50%/25%, 간격 16)과 1280×720 기준 Canvas 구역 하나를 담았다. 테스트는 원본 JSON 읽기·쓰기, 기본값, 잘못된 데이터 거부, 좌표 및 편집 경계, 실패한 편집의 상태 보존, 취소·복구, 템플릿 1~128개, 데스크톱 없는 CLI를 확인한다. 이식 범위와 원본과의 차이는 [크레이트 문서](../../crates/waytoys-zones/README.md)에 정리했다.

## 실제 준비·실행 절차

Windows의 위 작업 디렉터리에서 VM에 전달했다. VM의 Rust 환경과 SSH 공개 키 접근은 기존 준비 상태를 사용했다. 소스 동기화에서 `.git/`, `target/`, `.artifacts/`를 제외했다. PowerToys 참고 clone과 Windows의 산출물을 VM에 전송하지 않았다.

```powershell
wsl.exe -d Ubuntu-24.04 -e rsync -rt --exclude=.git/ --exclude=target/ --exclude=.artifacts/ -e /mnt/c/Windows/System32/OpenSSH/ssh.exe /mnt/d/Github/utils/way-toys/ debian@192.168.50.125:/home/debian/projects/way-toys/
```

첫 빌드 중 추가 의존성으로 lockfile을 갱신한 뒤 Windows로 가져왔고, 최종 검사는 모두 `--locked`로 실행했다. VM에서 rustfmt가 바꾼 새 크레이트의 파일도 Windows 작업 트리에 가져왔다. 다음은 최종 검사에 실제 사용한 원격 셸 본문이다. Windows PowerShell의 here-string을 SSH `bash -s`의 표준 입력으로 보냈고 출력을 보존했다.

```bash
set -eu
. "$HOME/.cargo/env"
cd /home/debian/projects/way-toys
date --iso-8601=seconds
cat /etc/os-release
uname -r
rustc -Vv
cargo --version
cargo build -p waytoys-zones --locked
cargo test --workspace --locked
cargo fmt --all -- --check
cargo clippy --workspace --all-targets --locked -- -D warnings
cargo tree -p waytoys-zones --edges normal --locked
env -u DISPLAY -u WAYLAND_DISPLAY -u DBUS_SESSION_BUS_ADDRESS target/debug/waytoys-zones validate crates/waytoys-zones/examples/custom-layouts.json
```

별도로 CLI의 `validate`, `preview ... 1 1280 720`도 `cargo run -p waytoys-zones --locked -- ...`로 실행했다. Grid 분할과 Canvas 이동은 CLI 통합 테스트가 실행하며 입력 파일이 유지되는지도 비교한다.

## 실패와 수정

- 최초 컴파일에서 설정 테스트의 색상 문자열과 Rust raw-string 구분자가 충돌해 구문 오류가 발생했다. 구분자를 수정한 후 컴파일했다.
- 자석 변환 테스트에서 `1.5 / 10000 * 10000`이 부동소수점상 정확한 1.5라고 가정해 39개 중 하나가 실패했다. 실제 값은 `1.4999999999999998`이므로 기대값을 수정하고 이진 표현이 정확한 중간값의 ties-to-even 사례도 추가했다. 알고리즘을 테스트 오차에 맞춰 바꾸지 않았다.
- Clippy가 Grid 테스트의 default 생성 후 필드 재할당 두 건을 지적했다. 구조체 초기화식으로 수정했다.
- 위 최종 묶음 검사는 빌드·46개 테스트·fmt·Clippy·의존성 출력까지 통과했지만 마지막 CLI의 파일 열기가 `No such file or directory`로 실패해 전체 셸 종료값은 1이었다. 같은 파일을 아래 SSH 명령 인수 방식으로 호출하자 정상 동작했다. 표준 입력 전달 경로의 줄 끝 문자가 원인으로 의심되지만 인수 바이트를 별도 추적하지 않았으므로 확정하지 않는다. 첫 실행의 실패 로그도 보존했다.

마지막 CLI는 Windows에서 다음 명령으로 다시 확인했다. 파일이나 프로그램을 수정하지 않았다.

```powershell
ssh debian@192.168.50.125 'cd /home/debian/projects/way-toys && env -u DISPLAY -u WAYLAND_DISPLAY -u DBUS_SESSION_BUS_ADDRESS target/debug/waytoys-zones validate crates/waytoys-zones/examples/custom-layouts.json'
```

이 명령의 실제 종료값은 0이고 출력은 `{"layout_count":2,"valid":true}`였다. 위 셸 본문을 Linux에서 직접 실행하거나 명령 인수로 전달하는 것은 재현 절차이며, Windows 표준 입력 경로의 실패를 성공으로 정리하지 않는다.

## 관찰 결과와 근거

- Zones 단독 빌드 성공. Zones 단위 테스트 39개, CLI 통합 테스트 3개, 기존 오버레이 테스트 4개 모두 통과했다(총 46개).
- workspace fmt 검사와 경고를 오류로 처리한 Clippy가 통과했다.
- Cargo 의존성 트리에 `waytoys-core`, `waytoys-overlay`, GUI·Wayland 라이브러리가 없다. 실행 파일의 사용자 레이아웃 검증도 DISPLAY·WAYLAND_DISPLAY·DBus 주소 없이 성공했다.
- `preview`의 Canvas 결과는 `(100,100,512,288)`로 입력 기준과 일치했다. CLI 통합 테스트는 Grid 결과 3개와 첫 x=16, 마지막 width=296을 확인했다.
- CLI 편집은 표준 출력으로 JSON을 반환했고, 다시 가져올 수 있었으며 입력 파일은 그대로였다. 잘못된 분할은 실패 종료하고 부분 JSON을 쓰지 않았다.
- 별도 읽기 전용 검토에서도 기능 간 코드 의존성 결함은 발견하지 못했다. 단, Cargo 메타데이터는 루트 workspace를 상속한다. 크레이트 디렉터리만 복사한 별도 프로젝트의 빌드를 보장하지 않는다.

실제 로그는 [최종 묶음 검사와 마지막 호출 실패](artifacts/2026-10-31-15/verification-first.log), [단독 CLI 성공](artifacts/2026-10-31-15/standalone.log)에 보존했다. 초기 개발 단계의 컴파일·테스트 실패 출력은 대화 실행 기록에 있으며 별도 원본 로그 파일은 보존하지 못했다.

## 한계와 정리

이는 Rust 모델과 조작 로직의 검증이다. PowerToys를 빌드·실행한 대조 시험, Windows 네이티브 빌드, GUI 편집과 오버레이 연결, 실제 다중 모니터 창 배치는 확인하지 않았다. 설정은 자체 JSON 형식이며 PowerToys settings.json의 래퍼를 직접 읽지 않는다. 사용자 레이아웃 형식은 원본을 따르지만 추가 검증 제약과 플랫폼별 DPI·반올림 차이가 있다.

검사는 compositor, 로그인 세션, 기존 창 배치와 VM 자원을 변경하지 않았다. 소스와 Cargo 산출물은 개발용 VM에 유지했다. 새 상주 프로세스나 전역 단축키를 등록하지 않아 별도 실행 정리는 필요하지 않았다. 커밋·푸시는 수행하지 않았다.
