
최초 `cargo test -p waytoys-zones-editor --lib`와 `cargo build -p waytoys-zones-editor`에서 추가 의존성을 받은 뒤 VM의 lockfile을 Windows로 가져왔다. 이후 최종 검사는 아래 순서로 실행했다. VM에서 rustfmt가 바꾼 새 크레이트 파일은 Windows에도 가져왔다.

## 실제 화면·입력 시험

Windows에서 아래 명령으로 시작했다. 잠겨 있던 테스트 세션은 기존 권한으로 해제했다. 첫 실행 전 위 검증용 config에는 저장된 Grid가 없었다.

```powershell
ssh debian@192.168.50.125 'sudo -n loginctl unlock-session 1; systemd-run --user --unit=waytoys-grid-editor-16 --collect --setenv=WAYLAND_DISPLAY=wayland-0 /home/debian/projects/way-toys/target/debug/waytoys-zones-editor --output Virtual-1 --config-dir /home/debian/waytoys-test-results/grid-editor-16/config'
scp scripts/vm-input.py INOPS-PVE:/tmp/waytoys-vm-input.py
```

실제 입력은 PVE의 VM 700 QMP 소켓에 `input-send-event`로 전달했다. 재현 도구는 [scripts/vm-input.py](../../scripts/vm-input.py)이며, 종료·오류 시 자신이 누른 상태로 남긴 버튼·키를 해제한다. 로컬 키보드나 다른 VM에 입력하지 않았다. Windows에서 실제 사용한 호출 형식은 아래와 같다.

```powershell
$fixture = 'docs/experiments/artifacts/2026-10-31-16/input-start.json'
$events = Get-Content -LiteralPath $fixture -Raw
$encoded = [Convert]::ToBase64String([Text.Encoding]::UTF8.GetBytes($events))
ssh INOPS-PVE "printf %s '$encoded' | base64 -d | python3 /tmp/waytoys-vm-input.py --vm-id 700 --width 1962 --height 627"
```

`--width/--height`는 이 시험에서 사용한 정규화 기준이다. 다른 배치에 그대로 적용하지 않는다. 모니터 경계를 넘는 최초 절대 이동에서 요청 위치와 게스트가 받은 위치에 약 100 논리 픽셀 차이가 관찰된 적이 있다. KWin 경계 저항 등이 원인일 수 있으나 확정하지 않았다. 앱 로그의 실제 surface 로컬 좌표를 기준으로 동작을 판정했다. 첫 화면으로 돌아오는 마지막 Cancel은 추가 이동 후 다시 눌렀다.

입력 파일의 실행 순서와 관찰 결과는 다음과 같다. 각 JSON은 실제 전송한 이벤트다.

1. [input-start.json](artifacts/2026-10-31-16/input-start.json): 첫 화면의 `(500,250)`을 클릭해 기본 3구역을 4구역으로 분할했다.
2. [input-virtual-1.json](artifacts/2026-10-31-16/input-virtual-1.json): 세로 경계를 x≈282→320으로 이동, 구역을 드래그 선택해 확정 병합(4→2), 모니터 전환 버튼을 눌렀다. 저장 여부 확인창이 표시됐다.
3. [input-virtual-2.json](artifacts/2026-10-31-16/input-virtual-2.json): `Save and switch`로 첫 화면을 저장하고 두 번째 화면으로 전환했다. 두 번째 화면에서 일반 클릭(3→4), Shift 클릭(4→5), 경계 이동을 수행했다. 실제 전달된 좌표는 앱 로그에 있다.
4. [input-save.json](artifacts/2026-10-31-16/input-save.json): Ctrl+S로 두 번째 화면의 5구역을 저장하고 닫았다.

그다음 아래 명령으로 다시 열었다. 재실행 캡처에서도 5구역과 조절된 폭이 유지됐고 수정 전 상태로 표시됐다.


5. [input-discard.json](artifacts/2026-10-31-16/input-discard.json): 5→6구역으로 수정한 뒤 `Discard`로 첫 화면에 돌아왔다.
6. [input-close.json](artifacts/2026-10-31-16/input-close.json): 추가 포인터 이동 후 첫 화면의 Cancel을 눌러 닫았다.

저장 직후와 Discard·Cancel 이후 파일 SHA-256이 같았다. 파일 원본도 보존했다.

## 실패·수정과 한계

- 첫 20개 테스트와 빌드는 통과했으나 Clippy가 미사용 import와 중첩 조건·배열 청크 관련 스타일을 지적했다. 새 크레이트에 `cargo clippy -p waytoys-zones-editor --all-targets --locked --fix --allow-dirty --allow-staged -- -D warnings`를 적용한 뒤 최종 전체 검사로 확인했다. 이 초기 lint 출력은 별도 로그 파일로 보존하지 못했다.
- 읽기 전용 검토에서 포인터 장치가 끊기면 resize 상태가 남을 수 있는 결함을 발견했다. `pointer_lost()`를 Leave·capability 제거·seat 제거에 연결해 스냅샷 복원과 입력 상태 정리를 수행하고 회귀 테스트 3개를 추가했다. 완료된 병합 확인창은 단순 포인터 이탈로 사라지지 않는다. 수정 뒤 재검토에서도 해당 결함 해소를 확인했다. 실제 장치 분리 대신 상태 테스트로 검증했다.
- 첫 원격 환경 조회는 Qt display 변수가 없어 실패했고 offscreen 조회는 가상 출력을 반환했다. 실제 출력 판단에는 `XDG_RUNTIME_DIR=/run/user/1000 WAYLAND_DISPLAY=wayland-0 QT_QPA_PLATFORM=wayland`를 명시한 조회와 앱 surface configure 값을 사용했다.
- 실제 출력 제거·해상도 변경·다른 GPU·물리 모니터·Windows 네이티브 실행은 이번 회차에서 시험하지 않았다. 화면 크기 변경과 입력 상실의 controller 복구는 단위 테스트가 다룬다.
- 실제 창 이동, 패널 제외 작업 영역, Canvas 에디터, 범용 설정 화면은 범위 밖이다. 커밋·푸시는 수행하지 않았다.

검증용 첫 두 unit은 정상 종료했다. PVE에 올린 `/tmp/waytoys-vm-input.py`는 시험 후 제거했다. `waytoys-zones-editor-dev`는 사용자가 바로 볼 수 있게 열어 두었으며 저장/취소로 닫을 수 있다. SSH에서 닫으려면 `systemctl --user stop waytoys-zones-editor-dev`를 실행한다. 소스와 테스트 결과는 개발 VM에 유지했다.
