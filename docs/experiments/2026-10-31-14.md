# 2026-10-31-14 PowerToys FancyZones 소스 구조 확인

## 목적과 기준

2026-10-31 KST, FancyZones의 실제 런타임·오버레이·레이아웃·편집기·저장 구조를 읽고 Waytoys에 참고할 경계를 정리했다. 기준은 Microsoft PowerToys `8827f848fbbac4afeedcae2907c71cd05fd5aa86`이다. Waytoys 작업 트리에는 이전 실험과 캡처 도구의 미커밋 변경이 존재한다.

분석 결과는 [FancyZones 소스 분석](../fancyzones-source-analysis.ko.md)에 있다. Windows PowerToys를 빌드·실행하지 않았고 성능·메모리·실제 배치 동작도 측정하지 않았다. 원본 소스는 수정하지 않았다.

## 실제 소스 확보 절차

Windows PowerShell, `D:\Github\utils`에서 실행했다.

```powershell
New-Item -ItemType Directory -Path D:\Github\utils\way-toys\.artifacts\references -Force | Out-Null
git clone --filter=blob:none --sparse --depth 1 https://github.com/microsoft/PowerToys.git D:\Github\utils\way-toys\.artifacts\references\PowerToys
```

복제한 PowerToys 디렉터리에서 실행했다.

```powershell
git sparse-checkout set src/modules/fancyzones src/common doc
git rev-parse HEAD
git log -1 --format='%h %cs %s'
rg --files -g AGENTS.md
rg --files src/modules/fancyzones
```

실제 실행 당시 HEAD는 위 고정 커밋이었다. 나중에 같은 내용을 다시 얻으려면 해당 커밋을 fetch/checkout한 뒤 sparse-checkout을 적용해야 한다. API의 현재 기본 브랜치가 같은 커밋일 것이라고 가정하지 않는다.

## 읽기·확인 방법

- 실제 파일 목록과 함수 시그니처·관련 코드 발췌를 먼저 수집하고 관련 파일을 선별한 뒤 원본을 읽었다. mandatory AGENTS 지침은 별도로 유지했다.
- `FancyZonesLib.vcxproj`와 호출부를 대조해 현행 드래그 구현이 `WindowMouseSnap`임을 확인했다. 남아 있는 `WindowDrag.cpp`는 현행 흐름의 근거로 쓰지 않았다.
- 런타임 이벤트와 레이아웃/편집기 영역을 독립적으로 읽고, 오버레이 생성·표시·렌더링·해제와 좌표 변환을 교차 확인했다.
- 결과 문서에 고정 커밋의 파일·행 링크를 넣었다. 원본 작업 트리가 깨끗함을 확인했다.
- Canvas에는 같은 분석 내용을 입력 수집→드래그→출력/구역→오버레이→정상 드롭→취소 흐름으로 정리했다. SDK 공개 타입을 읽고 작성했으며 이 세션에서 호스트의 Canvas 렌더링 및 TypeScript 자동 진단은 확인하지 못했다.

## 확인 결과와 한계

작업 영역별 네이티브 창과 Direct2D 표시, 전역→작업 영역 좌표 변환, 드롭/취소 분리, 별도 WPF 편집기와 역할별 JSON 저장 구조를 소스에서 확인했다. Waytoys 적용 제안은 아직 구현·검증된 것이 아니다. 코드 변경이 없는 소스 조사이므로 PowerToys 빌드/실행 시험은 수행하지 않았다. 캔버스 파일은 관리 폴더에 두고, 상세 소스 근거는 저장소 문서에 보존했다.
